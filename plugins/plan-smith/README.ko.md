## 실측 결과 — 이 스킬이 토큰 값을 하는 이유

아래 주장은 전부 추정이 아니라 lab 실측이다(데이터: z-lab `plan-smith-lab/`의 `tco/`, `transfer/` 계열).

**작동하는 산출물까지의 총비용** (수리 루프 포함 · 약한 구현자 · 고정 수리 프롬프트 · arm당 4체인):

| 단계 | baseline plan | plan-smith v1.4 |
|---|---|---|
| 플랜 (opus) | 229k | 689k — **3.0배 비쌈** (스킬 문서 4종 열람) |
| 구현 ×4 (haiku) | 6,968k | 4,069k — **42% 절감** |
| 완성까지 수리 | **8,380k** (4라운드) | **620k** (1라운드) — **13.5배 절감** |
| **작동하는 산출물 4개 총계** | **15.58M** | **5.38M — 65.5% 절감** |

어림수로: 베이스라인 100 + 수리 116 = 216, plan-smith는 66으로 완결. 숫자만이 아니라 메커니즘:
수리 프롬프트는 양쪽 동일한 고정 템플릿이었으므로 격차는 **플랜이 만들어내는 결함의 종류**에서 났다 —
plan-smith의 유일한 실패는 복사 블록이 못 덮은 심볼 하나(한 줄 수리, 그 체인은 실험 계열 최초의
스테이지 클리어로 종료)였고, 베이스라인의 실패는 컴포넌트 간 계약 불일치(인터페이스 재구성 1건,
3라운드 두더지잡기 1건)였다.

**영수증 있는 부가효과:** URL을 복사 문자열로 바꾼 뒤 유령 의존성 버전 5건 → 0건 · 4/4 반복이 동일
CDN 줄·동일 파일 구성 재현 · 전체 실험 계열의 스테이지 클리어는 전부 plan-smith 셀에서 나옴.

**같은 문단에 적는 한계:** 수리 표본이 작고(2체인 대 1체인), 과제 1종·약한 구현자 1종 — 강한
구현자에서는 격차가 줄어든다(강한 모델은 스킬 없이도 성공한다). 베이스라인 수리비의 절반은
단일 체인에서 나왔다.

## 진입점

```
/plan-smith:plan-smith [frame=<프레임>] [style=opus|fable|relay|auto] <태스크 설명>
```

자연어 요청("… 플랜 짜줘")으로도 스킬이 트리거됩니다. 산출물: `plans/<slug>/{packet.md, plan.md[, draft.md, audit.md]}`.

## 설계 불변식

1. 메인 에이전트는 **플랜을 직접 쓰지 않는다** — 의도만 증류한다. 추출은 컨텍스트 잡음을 견디지만 집필은 못 견딘다.
2. **확인된 패킷 없이 집필 없음** — 추측 필드는 전부 `⚠guess` 표시 후 사용자와 해소한다. 판단이 애매하면 즉시 묻는다.
3. 집필자의 입력은 **자기완결** (패킷 + 인라인 프레임/스타일 스펙) — 세션 접근 없음, 경로 추측 없음.
4. **원문 릴레이** — 플랜 파일은 전문 제시. 요약은 규약 위반.
5. 스타일은 **모델 선택이 아니라 프롬프트 규율** — 26개 플랜 통제 실험에서 증류되고 100플랜 검증 코퍼스로 스트레스 테스트되었다. relay 직렬 연결과 모델 간 이식성은 아직 '유망하나 미검증'이며, 회고 데이터가 그 증거를 축적한다.
